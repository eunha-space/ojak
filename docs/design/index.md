Design records
==============

These are design records, not descriptions of what Ojak does today.  They set
the direction for turning Ojak from a set of protocol primitives into a
framework that ActivityPub applications are built on.

 -  [Ojak as an application framework](./framework.md): the governing rule, the
    problem, and the steps.
 -  [Serving](./serving.md): what Ojak answers when another server, or a
    person, sends a GET.
 -  [The inbox](./inbox.md): what Ojak does with an activity another server
    POSTs.
 -  [Portable objects](./portable.md): objects whose identity is a key rather
    than a host (FEP-ef61).
